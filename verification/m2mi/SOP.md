# M2MI Memory Ingest walkthrough

1. Build the committed web bundle, then start the isolated fixture on port 8784.
2. Open the fixture and confirm the unmistakable `M2MI REGRESSION FIXTURE` marker.
3. On the Work layer, confirm **Memory Ingest** wears the ordinary Stage title,
   drag, settings, remove, and resize controls. Confirm the header has no queue
   launcher.
4. In **Start with your agent files**, confirm the repository's real `AGENTS.md`
   appears as an offer. No memory batch may exist yet.
5. Activate **Queue for review**. Confirm the same module renders the resulting
   document with its reviewable children and explicit **Reject document** /
   **Approve document** actions. The status must say nothing entered the Palace.
6. Reload. Confirm the document remains pending and the offer says **Waiting for
   review**; nothing has auto-admitted.
7. Resize Memory Ingest, remove it, and restore it from the Stage library. Its
   consent surface must return through the ordinary module lifecycle.
8. Repeat the review state at 390x844. Agent-file path, actions, memory bodies,
   and status must remain readable without horizontal scrolling.

The fixture composes the production owner app and the real repository
`AGENTS.md` file with deterministic local model and Palace doubles. It proves
layout, discovery, and consent behavior only; it makes no provider or owner-data
claim.

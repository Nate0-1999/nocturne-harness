# M2UX6 real owner-app SOP — 2026-08-21

This walkthrough used `harness.packaged:create_app` from the M2UX6 checkout,
the current production web build, and the owner's configured live Palace. The
app journal and receipts were isolated under a temporary `NOCTURNE_HOME`. It
did not use `scenario_app.py`, send a prompt, make a provider call, or write to
the Palace.

## Procedure and observations

1. Opened the live Rack at `1280 × 900` and waited for the Header to report
   **Palace ready**. Live Vitals resolved, including spend lanes and Palace
   gauges; the stage mounted eight real sandboxed module frames.
2. Opened **App settings**, selected **WIZARD MODE**, and closed settings.
   The host and all eight frames reported `wizard-mode`. The Elvish module-head
   strip was a data-URI asset with `grimoire-rune-inscribe`, one iteration, and
   a rendered width below the 7.5rem cap. The right-margin strip was present.
3. Inspected the rendered stage and the Stage Library. Both used the same
   scriptorium materials, and **Close stage library** returned directly to the
   stage.
4. Selected **TECHNOMANCER**. The host and all eight frames reported
   `technomancer`. The machine-hand head strip and module-bottom hexline were
   finite, one-iteration conjurations. The scanline remained the only checked
   infinite host motion and was attached to `.rack-ambient`, not owner data.
5. Reloaded the owner app. TECHNOMANCER persisted in the host and all eight
   frames.
6. Restored **NEO-NOIR** before closing the browser. Host and frame theme state
   agreed, and the browser warning/error log was empty.

The live Palace currently returns older Memory/Queue records without the
newly-required `origin_thread_id` field. Those reads therefore showed the
existing plain failure state while live Vitals continued to resolve. This is
an adjacent schema-compatibility issue, not a theme failure; M2UX6 made no
model, Palace, or data-contract change.

Live screenshots were inspected in-session but not retained because the real
Palace is not a fixture identity. All checked-in images use the explicit
M2UX6 verification curtain.

PASS. Both grimoire themes are selectable, cross-frame complete, persistent,
